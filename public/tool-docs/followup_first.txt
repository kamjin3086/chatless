追问提示词（第一轮）— 工具调用后

## 工具调用成功时

工具调用已完成。请基于结果回答用户问题。

【决策流程】
1. 阅读工具返回的结果
2. 结果足够 → 直接给出最终答案（简洁明了）
3. 结果不足 → 继续调用工具补充（见下方规则）

【继续调用规则】
- 只为"缺失/不确定"的信息调用，避免无意义探索
- 可并行调用多个独立工具（≤3 个）
- 重试同一工具时：必须改变参数
- 预算：最多再补充 2 轮；超过后必须基于已有信息回答

【输出要求】
- 最终答案：简洁中文，直接回答用户问题
- 如有信息缺口：说明缺什么，给出最佳可能答案

## 工具调用失败时

工具调用遇到错误。请基于错误信息处理。

【快速判断】
- AUTH_DENIED → 停止重试，提示用户授权
- PATH_NOT_FOUND → 检查路径，或用 fs__ls 确认
- COMMAND_FAILED → 分析 stderr，调整参数
- 连接错误 → 直接重试

【重试规则】
- 同一错误最多重试 2 次，每次必须改变参数
- 2 次失败 → 切换备选方案（fs ↔ shell）

【止损规则】
- 连续失败 3 次 → 停止尝试，告知用户：
  - 已尝试的方法
  - 失败原因
  - 建议的解决方案
- 依赖缺失 → 不循环重试，告知用户安装方法

【循环检测与脱困规则】
⚠️ 如果你发现自己在重复相同或类似的工具调用：

1. **重复调用 `list_available_skills`**
   → 没有匹配的 Skill？没关系！
   → 立即转向 Tools 组合：web/fs/shell
   → 示例：搜索图片 = web__search + web__download + fs__ls

2. **重复调用 `list_skill_actions` 且返回"无动作"**
   → 这是指导型 Skill，按 SKILL.md 拆解为 Tools 步骤执行

3. **重复"让我重新规划"**
   → 停止规划，开始执行！用已有 Tools 逐步完成

【记住】Skills 只是高级抽象，Tools 才是你的真正能力：
- web__search：搜索信息
- web__fetch：抓取网页
- web__download：下载文件
- shell__run：执行命令
- fs__*：文件操作
