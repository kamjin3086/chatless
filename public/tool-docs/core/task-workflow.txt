【复杂任务四步流程】（Research-Plan-Execute-Verify）

适用场景：预估步骤 >3 步，或涉及多文件/多工具的任务

================================================================================
第一步：研究（Research）
================================================================================

目标：充分理解任务，收集必要信息

操作：
1. 识别用户的核心目标和约束条件
2. 如有歧义，先简短提问再行动
3. 主动探索：
   - 不确定文件结构 → list_directory 探索
   - 不确定文件内容 → read_file 查看关键文件
   - 不确定环境 → 运行检测命令（如 python --version）
4. 研究结果：明确列出已知条件和待确认项

研究输出示例：
```
【研究结果】
目标：将 Word 文档转换为 PDF
已知条件：
- 源文件：C:/Users/test/doc.docx
- 输出位置：同目录
待确认：
- pandoc 是否已安装？
- 是否需要保留格式？
```

================================================================================
第二步：规划（Plan TodoList）
================================================================================

目标：制定清晰的执行计划

格式要求：
```
任务：{用户目标的一句话描述}

步骤：
1. [ ] {具体操作描述}
2. [ ] {具体操作描述}
3. [ ] {具体操作描述}
...

预计风险：{可能遇到的问题}
```

规划原则：
- 每个步骤应该是可验证的原子操作
- 破坏性操作（删除/覆盖/推送）单独列出并标注 ⚠️
- 不确定的步骤加 [?] 标记，执行前确认
- 复杂步骤可拆分为子步骤

规划输出示例：
```
任务：将 doc.docx 转换为 PDF

步骤：
1. [ ] 检查 pandoc 是否已安装
2. [ ] 确认源文件存在
3. [ ] 执行转换命令
4. [ ] 验证输出文件
5. [?] 清理临时文件（如有）

预计风险：
- pandoc 未安装 → 需用户手动安装
- 文档包含特殊格式 → 可能需要额外参数
```

================================================================================
第三步：行动（Execute）
================================================================================

目标：按计划逐项执行

执行原则：
- 严格按 TodoList 顺序执行
- 每完成一项，更新状态：[ ] → [x]
- 遇到错误时：分析原因，决定重试/换方案/止损
- 需要调整计划时：先说明原因，再更新 TodoList

进度汇报（每 2-3 步或关键节点）：
```
[进度] 已完成 3/5 步
[x] 步骤1：pandoc 已安装 (v3.1.2)
[x] 步骤2：源文件存在 (doc.docx, 15KB)
[x] 步骤3：转换命令已执行
[ ] 步骤4：正在验证输出...
```

错误处理：
- 可恢复错误 → 调整参数重试（最多 2 次）
- 不可恢复错误 → 更新计划或止损
- 止损条件：同一目标连续失败 3 次

================================================================================
第四步：确认（Verify）
================================================================================

目标：验证任务完成，确保结果正确

验证清单：
1. 输出文件存在？→ list_directory 或 read_file 确认
2. 内容正确？→ 读取关键部分验证
3. 格式符合要求？→ 检查文件类型、编码、大小
4. 无副作用？→ 确认没有意外修改其他文件

完成汇报格式：
```
[完成] 任务已完成

结果：
- 输出文件：C:/Users/test/doc.pdf
- 文件大小：128KB
- 关键内容：（前几行或摘要）

验证：
- [x] 文件已创建
- [x] 文件大小合理
- [x] 无错误日志
```

失败汇报格式（如适用）：
```
[未完成] 任务部分完成

已完成：
- [x] 步骤1-2

未完成：
- [ ] 步骤3：pandoc 转换失败，缺少字体支持

建议：
1. 安装缺失字体：sudo apt install fonts-noto
2. 或使用 --pdf-engine=wkhtmltopdf 参数
```

================================================================================
简单任务处理（≤3 步）
================================================================================

简单任务无需完整四步流程，直接执行即可：
1. 执行操作
2. 验证结果
3. 汇报完成

示例：
```
用户：读取 config.json 的内容

执行：调用 read_file
结果：已读取，内容如下...
```
