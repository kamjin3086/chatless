【文件导向的 Agent 工作流】

================================================================================
核心理念
================================================================================

"文件系统是 Agent 的外部大脑"

使用 ctx__* 工具自动管理上下文：
1. 研究结果 → ctx__save_research（避免上下文溢出）
2. 任务计划 → ctx__save_plan（防止目标漂移）
3. 错误记录 → ctx__log_error（跨轮次学习）
4. 检索上下文 → ctx__get（按需加载）
5. 更新进度 → ctx__update_step（跟踪执行）

工作目录：@WorkDir/.agent/（自动创建）

================================================================================
适用场景判断
================================================================================

何时启用文件导向模式：
- 预估步骤 > 3 步
- 涉及大量数据收集/分析
- 需要跨多次对话延续
- 用户明确要求"记录过程"

何时使用轻量模式（仅上下文）：
- 简单任务（≤3 步）
- 一次性查询
- 不涉及复杂状态

================================================================================
工具使用指南
================================================================================

## 1. 创建任务计划

```
ctx__save_plan({
  title: "批量转换文档格式",
  goal: "将 docs/ 下所有 .docx 转换为 .md",
  steps: [
    "扫描目录找到所有 .docx 文件",
    "逐个调用 pandoc 转换",
    "验证输出文件完整性"
  ],
  constraints: ["保留原始文件"],
  risks: [
    { risk: "pandoc 未安装", fallback: "提示用户安装" }
  ]
})
```

## 2. 保存研究结果

```
ctx__save_research({
  topic: "market-analysis",
  content: "## 竞品分析\n- 竞品A: xxx\n- 竞品B: yyy",
  source: "https://example.com/report",
  keyFindings: ["发现1", "发现2"]
})
```

## 3. 记录错误

```
ctx__log_error({
  operation: "pandoc 转换 report.docx",
  error: "Font not found: SimHei",
  analysis: "系统缺少中文字体",
  resolution: "改用 wkhtmltopdf"
})
```

## 4. 检索上下文

```
// 获取当前计划和进度
ctx__get({ type: "plan" })

// 获取特定研究
ctx__get({ type: "research", topic: "market-analysis" })

// 列出所有研究主题
ctx__get({ type: "research" })

// 检查之前的错误
ctx__get({ type: "errors", limit: 10 })

// 获取工作目录状态
ctx__get({ type: "status" })
```

## 5. 更新步骤状态

```
ctx__update_step({
  stepIndex: 2,
  status: "done",
  note: "成功转换 15 个文件"
})
```

状态类型：done/failed/skipped/in_progress

================================================================================
标准工作流程
================================================================================

### 复杂任务执行流程

1. **评估任务** → 判断是否需要启用文件导向模式
2. **创建计划** → ctx__save_plan
3. **研究阶段** → 收集信息 → ctx__save_research
4. **执行阶段** → 逐步执行 → ctx__update_step
5. **遇到错误** → ctx__log_error
6. **验证结果** → 检查输出，总结报告

### 会话恢复协议

用户开始新对话时：

1. 检查状态：ctx__get({ type: "status" })
2. 如有未完成任务 → ctx__get({ type: "plan" })
3. 询问用户是否继续
4. 用户确认后从断点继续

================================================================================
与其他工具的关系
================================================================================

| 工具类型 | 用途 | 示例 |
|----------|------|------|
| ctx__* | Agent 自身的上下文管理 | 计划、研究、错误 |
| fs__* | 用户数据的文件操作 | 读写用户文件 |
| web__* | 网络操作 | 搜索、抓取、下载 |
| shell__run | 执行命令 | git、npm、python |

**原则**：
- ctx__* 管理 Agent 的工作状态
- fs__* 操作用户的数据文件
- 两者分工明确，可以配合使用

================================================================================
文件结构
================================================================================

所有上下文文件存储在 @WorkDir/.agent/：

```
.agent/
├── todo.md              # 任务计划（ctx__save_plan）
├── errors.log           # 错误日志（ctx__log_error）
└── research/            # 研究结果（ctx__save_research）
    ├── topic-a.md
    └── topic-b.md
```

================================================================================
轻量模式 vs 完整模式
================================================================================

| 特征 | 轻量模式 | 完整模式（ctx 工具）|
|------|---------|---------------------|
| 适用场景 | ≤3 步简单任务 | >3 步复杂任务 |
| 研究结果 | 保留在上下文 | ctx__save_research |
| 任务计划 | 口头描述 | ctx__save_plan |
| 错误记录 | 当场处理 | ctx__log_error |
| 断点续做 | 不支持 | 支持 |
| Token 消耗 | 较高 | 较低（按需加载）|
