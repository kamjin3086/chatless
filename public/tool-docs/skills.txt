Skills (skills__*) — 工具使用指南

## 用途
Skills 是预定义的任务模板（SKILL.md + actions），提供特定场景的最佳实践。
使用 skill 时，它将成为权威的分步指南。

## 何时使用（重要）
仅在以下情况使用 skills：
- 用户显式提到 skill（skill id/name，或 @skill 语法）
- 从技能索引中，你高置信度地判断某个 skill 直接匹配任务

否则（无显式提及，任务与现有 skills 无关）：不要调用 skills 工具，直接用 filesystem/shell_executor 完成。

## 技能不匹配时的处理（关键！）

⚠️ **Skills 只是高级抽象，Tools 才是真正的能力！**

当没有匹配的 Skill 时，**不要反复查询 skills，而是转向组合使用已注册的 Tools**：

### 可用的基础 Tools（你的手和眼）
- `web_search__search`：网络搜索（新闻、图片、信息）
- `web_search__fetch`：抓取网页内容
- `filesystem__*`：文件读写、目录操作
- `shell_executor__execute_command`：执行命令（下载、转换、处理）

### 正确决策流程
1. 调用 `list_available_skills` **一次**
2. 有匹配的 Skill → 使用 Skill
3. **没有匹配的 Skill → 立即停止 skills 工具，转向 Tools 组合**
4. 分析任务需要哪些能力 → 组合使用 web_search/filesystem/shell_executor

### 示例
- 用户："搜索猫的图片并保存"
  - 没有图片搜索 Skill？没关系！
  - 方案：`web_search__search(猫 图片)` → 获取图片 URL → `shell_executor(curl下载)` → `filesystem(保存)`
  
- 用户："翻译这个网页"
  - 没有翻译 Skill？
  - 方案：`web_search__fetch(url)` → 获取内容 → 直接翻译并回复

### ⚠️ 禁止的行为
- 反复调用 `list_available_skills`（已经查过一次了！）
- 只因没有 Skill 就说"无法完成"（还有 Tools 呢！）
- 忽略已注册的 web_search/filesystem/shell_executor 工具

## 标准工作流
1. 先调用 `skills__get_skill_instructions({ skillId })` 获取指导
2. 如有 actions，调用 `skills__list_skill_actions({ skillId })` 查看可用操作
3. 使用返回的 actionId 执行操作（不要猜测 actionId）
4. 如仅有指导无 actions：分解为 filesystem/shell_executor 步骤执行
5. 用 filesystem 验证输出结果

## 高效阅读（行范围）
- `skills__get_skill_instructions` 支持 `startLine`/`endLine` 参数（1-based），返回 `totalLines`
- 优先按行范围读取相关部分，避免将整个 SKILL.md 拉入上下文

## 与文件导向工作流结合

### Skill 内嵌工作流模板
高级 Skill 可在 SKILL.md 中定义工作流模板：

```markdown
## 工作流模板（可选）

执行此 Skill 时，建议创建以下文件结构：

@WorkDir/.agent/
├── todo.md          # 任务计划（使用下方模板）
├── research/        # 研究结果目录
└── output/          # 最终输出目录

### todo.md 模板
任务：{skill 名称} - {用户目标}
状态：进行中

步骤：
1. [ ] {skill 定义的步骤1}
2. [ ] {skill 定义的步骤2}
...
```

### Agent 行为
当 Skill 包含工作流模板时：
1. 读取 Skill 指导
2. 检测到工作流模板 → 在 @WorkDir/.agent/ 创建对应结构
3. 用模板初始化 todo.md
4. 按 todo.md 逐步执行，每完成一步更新状态
5. 研究结果写入 research/*.md，最终输出写入 output/

### 会话恢复
用户中断后返回：
1. 检查 @WorkDir/.agent/todo.md
2. 如存在未完成的 Skill 任务，询问用户是否继续
3. 用户确认后，从断点继续

## 重要语义
- "保存了脚本" ≠ "任务完成"，必须执行命令并验证输出
- 研究结果写入文件后，上下文只保留摘要
- 每步完成后更新 todo.md 状态
