# 常见问题与故障排查

中文 | [English](faq-en.md)

## Chatless 安装后打不开怎么办？

- **Windows 启动后立即退出**：部分系统需要安装微软的 [Visual C++ 运行库（x64）](https://aka.ms/vs/17/release/vc_redist.x64.exe)。
- **macOS 打不开，或 Linux 安装包无法运行**：先确认下载的安装包适合你的系统和处理器，再参照[安装指南](../INSTALLATION_INSTRUCTIONS.md)中对应平台的步骤。

## 能连接提供商，但为什么发不了消息？

在**设置 → AI模型**中打开当前使用的提供商。显示可连接只代表服务可访问，不代表密钥有效，也不代表当前模型已经授权。

| 现象 | 先检查什么 |
| --- | --- |
| `401` / `403`，密钥无效或没有权限 | 确认密钥属于所选提供商，仍然有效，而且该账号有权使用所选模型。 |
| `404`，接口地址不正确 | 对照提供商文档检查服务地址和 API 路径。地址应是 API 基础地址，不是网页链接或完整的聊天请求地址；也确认模型 ID 是否正确。 |
| 连接被拒绝、超时或无法解析地址 | 核对服务地址和端口。如果是本地服务，确认它正在运行；如果是远程服务，确认当前网络可以访问它。 |

## 提供商返回 `429` 或提示“请求过于频繁”怎么办？

先暂停，不要连续重试。如果提供商给出了等待时间（例如 `Retry-After`）或限流重置时间，请等到该时间过后，再用**原来的提供商、模型和设置**重试一次。若回复旁有**重试**按钮，可以用它；否则重新发送原消息。

如果仍然收到 `429`，到提供商后台查看频率限制、剩余额度或账单状态。如果额度已经用完，短时间等待通常无济于事；Chatless 不能重置提供商的限制。

## 为什么找不到 Ollama 的本地模型？

1. 确认 Ollama 服务已启动。在**设置 → AI模型**中选择 **Ollama**，核对服务地址。本机默认地址是 `http://localhost:11434`，不要加 `/v1`。
2. 如果 Ollama 在本机运行，在终端查看已安装的模型：

   ```bash
   ollama list
   ```

3. 如果列表里没有目标模型，先在 Ollama 中安装它，再回到 Chatless 刷新模型列表。如果命令连不上服务，先检查 Ollama 是否正在运行；如果使用了远程 Ollama，请在配置的那台服务上核对模型列表，而不是检查本机列表。

## 排查后还没解决，如何反馈？

1. 在**设置 → 关于**查看版本。记录操作系统版本、处理器架构、复现步骤、预期行为和实际错误。如果是模型问题，带上提供商名称、模型 ID 和已试过的步骤。
2. 如果需要日志，在**设置 → 高级 → 日志系统**中选择**导出日志**，只截取与出错时间有关的片段。**调试**级别可能记录完整请求内容；如果临时启用了它，复现后请恢复原级别。
3. 上传前，从日志、截图和错误文本中删除 API 密钥、令牌、私人对话、文件路径和其他敏感信息。不要直接上传整份日志或数据库。
4. 先[搜索已有 Issue](https://github.com/kamjin3086/chatless/issues)，再从[模板选择页](https://github.com/kamjin3086/chatless/issues/new/choose)选择 **Bug report**。也可以从**设置 → 关于 → 提交反馈**打开反馈页面。可以用中文或任何能准确描述问题的语言填写，不必翻译。

使用疑问可以发到 [GitHub Discussions](https://github.com/kamjin3086/chatless/discussions)。安全漏洞请按[安全政策](../SECURITY.md)私下报告，不要发到公开 Issue 或讨论。
