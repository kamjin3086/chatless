# Android document phone check (#216)

Use an ARM64 debug APK and a tool-capable model. Record the APK revision, device, Android version, file provider, model, and observed result for each step. Do not use private data in the fixtures.

1. In a new chat, type a draft. Under **+ → Attach document**, open the Android document picker, then press Back. The draft and conversation stay unchanged. Pick a text PDF whose answer is on page 2 after a blank or image-only page. The attachment shows its filename and explains excerpt disclosure before sending. Picking alone does not make a model request.
2. Ask for the fact on page 2. Confirm the answer can cite the filename and the actual page, and check the bounded excerpt in the tool result. Ask a second question with Chatless automatic approval off; no new file selection or approval should be needed. If observing provider requests with a test endpoint, check that they contain neither the original file nor extracted body before the document tool responds; only bounded tool results may follow.
3. Force-stop and reopen Chatless. Open the same chat, verify the attachment label returns, and ask another question. Open a different chat; it must not see the previous chat's document. Return, replace it with plain UTF-8 text containing a blank line, and ask a question answered on line 3. Verify the new filename and line locator.
4. While a document is attached, cancel a replacement, then try an image-only PDF, a corrupt or inaccessible PDF, and a file over 8 MiB (or a PDF over 200 pages). The existing attachment and draft stay intact. Verify the OCR or file error is readable, no spinner remains, and the picker can be used again. Try an unsupported type; the system picker may filter it out, or Chatless must refuse it if the provider offers it.
5. Remove the attachment and ask a question in the same chat. No further document lookup is available. The original file remains outside Chatless. Attach again, delete that conversation, and confirm no document shows up in another chat or after reopen. Repeat selection and removal in light/dark mode and with larger text.

Limits are 8 MiB input, 200 PDF pages, and 1 MiB local extracted text. A search returns at most three 240-character matches. A read returns at most 1,200 characters from one PDF page or up to 12 text lines. Removal does not erase prior messages or excerpts already shared with a provider.
