# "Always" stays one word with two meanings; the promotion grid is enumerated

An approval answer is `once`, `always` or `unrestricted`. `always` does something different per scope: for the filesystem it remembers the containing directory with everyday permissions (and refuses to remember anything for a delete), for the shell it turns prompts off globally and persistently. `unrestricted` is conversation-scoped for both. One word, two meanings, and a third meaning we declined to add.

We kept the overloaded word rather than splitting it into scope-specific answers, because renaming would reach UI copy and stored approval records for no behavioural gain. In exchange, `planFilesystemPromotion` and `planShellPromotion` enumerate all six cells of answer × scope explicitly — no default branch — so an extraction or an added answer cannot silently drop a cell. The grid is pinned by tests, including the delete exception.

Considered and rejected: scope-specific answer names (`remember-directory`, `allow-always`). Genuinely clearer, but it changes what the approval cards offer and what the approval records already say - `agent_approvals` keeps one row per call with a `status` of pending/approved/rejected/expired, and the answer itself is not a column; the durable effect of `always` lives in the allowlist store instead.

Amendment (where the conversation cell actually executes). The grid says `unrestricted` is conversation-scoped, and it is - but not through the `conversationUnrestricted` field: nothing reads that field today. The pipeline executes the same answer as a *narrow* grant: the filesystem gets the approved directory granted for the conversation (recursively, except a delete, which grants the directory itself), shell gets a conversation grant keyed `shell`, every other server gets a `server:tool` grant (`knowledge`'s three reads collapse into one bucket). So "conversation-scoped" means per-directory / per-scope / per-tool depending on scope - never a blanket mute - and changing what `unrestricted` unlocks means changing those grants, not the planner's third column.

Status: accepted. The two promotion planners and the tests that pin the grid shipped with PR #85 (merged 2026-10-12); the `agent_approvals` schema and the approval cards described above are on `main` today.
